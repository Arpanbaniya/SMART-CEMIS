1. TRENDING EVENT ALGORITHM
================================================================================

Algorithm Type: Weighted Multi-Factor Scoring System
Time Complexity: O(n) where n = number of events
Space Complexity: O(n) for storing event scores

FORMULA:
--------
trendingScore = (velocityScore * 0.4) + (recencyScore * 0.35) + (categoryBoost * 0.25)

Where:
  velocityScore = participantCount / max(capacity, 1)
  
  recencyScore = max(1 - (ageInDays / 30), 0)
                 ageInDays = (currentTime - eventCreatedTime) / 86400000
  
  categoryBoost = 1.2 if category in [technology, competition, workshop, academic]
                = 1.0 otherwise

COMPONENT BREAKDOWN:
--------------------
1. Velocity Factor (40% weight):
   - Measures participation rate relative to event capacity
   - Calculated as: registeredUsers / totalCapacity
   - Range: 0 to 1
   - Higher participation = higher trending score

2. Recency Factor (35% weight):
   - Newer events score higher, decay over 30 days
   - Recent events (0-1 day old): score ~1.0
   - Events 15 days old: score ~0.5
   - Events 30+ days old: score ~0.0
   - Time decay formula: 1 - (daysSinceCreation / 30)

3. Category Boost (25% weight):
   - Tech-related and competitive events get 20% bonus
   - Boosted categories: technology, competition, workshop, academic
   - Normal categories: 1.0x multiplier
   - Boosted categories: 1.2x multiplier

FILTERING:
----------
- Excludes: completed, archived, cancelled events
- Requires: endTime >= currentTime (event still ongoing or upcoming)
- Returns: Top N events sorted by trendingScore descending

USE CASES:
----------
- Display "Trending Events" section on user dashboard
- Global trending rankings updated per API request
- No user personalization (same for all users)
- Performance: Optimized for 1000+ events via single pass

IMPLEMENTATION FILES:
- Backend: /backend/src/services/trendingService.ts
- API Endpoint: GET /api/events/trending?limit=10

2. RECOMMENDATION SYSTEM ALGORITHM
================================================================================

Algorithm Type: Hybrid Recommendation (Content-Based + Collaborative Filtering)
Time Complexity: O(n * m) where n = users, m = events
Cache Strategy: In-memory 5-minute TTL per user

OVERALL ARCHITECTURE:
---------------------
Step 1: Fetch Content-Based Recommendations (parallel)
Step 2: Fetch Collaborative Filtering Recommendations (parallel)
Step 3: Merge and blend scores from both models
Step 4: Deduplicate and filter out already-registered/completed events
Step 5: Sort by final score and return top-3

HYBRID BLENDING FORMULA:
------------------------
finalScore = (contentBasedScore * 0.5) + (collaborativeScore * 0.5)

Where merged recommendations are deduplicated with highest score winning.


--- COMPONENT 1: CONTENT-BASED FILTERING ---

Algorithm: Cosine Similarity (Vector Dot Product)

SIMILARITY CALCULATION:
  similarity = (UserVector . EventVector) / (|UserVector| * |EventVector|)
  
  Where:
    . = dot product (sum of element-wise products)
    |V| = magnitude = sqrt(sum of all elements squared)
    Range: 0 to 1 (0 = no similarity, 1 = perfect match)

VECTOR DIMENSIONS (16 total):
  [0-9]:   10 event category features (sports, technology, cultural, etc.)
  [10-14]: 5 interaction metrics (registrations, attendance, ratings, etc.)
  [15]:    1 recency factor (recent events score higher)

USER VECTOR CREATION:
  From user profile: preference field (physical or innovative)
  From past behavior: categories of registered/attended events
  Weighted by: registration frequency, attendance rate, ratings given

EVENT VECTOR CREATION:
  From event data: category (10 dimensions, one-hot encoded)
  From engagement: normalized participant count, capacity ratio
  From timing: recency decay factor

FINAL CONTENT-BASED SCORE:
  contentScore = (similarityScore * 0.7) + (confidenceScore * 0.3)
  
  Where:
    confidenceScore = (popularityFactor * 0.6) + (recencyFactor * 0.4)
    popularityFactor = min(participantCount / max(capacity, 1), 1)
    recencyFactor = dimension[15] of event vector


--- COMPONENT 2: COLLABORATIVE FILTERING ---

Algorithm: User-User Similarity + Predicted Ratings

USER SIMILARITY CALCULATION:
  Find N similar users based on shared event interactions
  Similarity = common events interactions / distance metric
  
  For each common event:
    Both users' ratings/behaviors are compared
  
  Pearson Correlation-like approach:
    Looks at rating patterns across shared events
    Higher correlation = more similar user preferences

PREDICTED RATING:
  For target user U predicting event E:
  
  predictedRating = SUM(similarUser.rating * similarityScore) / SUM(similarityScores)
  
  Where:
    similarUser = other user with high similarity to U
    similarUser.rating = that user's rating for event E
    similarityScore = correlation between U and similarUser
    
  Range: 1-5 (star rating scale)

FINAL COLLABORATIVE SCORE:
  collaborativeScore = (similarityToUser * 0.6) + (predictedRating / 5 * 0.4)
  
  Where:
    similarityToUser = how similar current user is to recommendation source
    predictedRating / 5 = normalized predicted rating (0-1 range)


--- HYBRID MERGING ---

DEDUPLICATION LOGIC:
  Create merged map: eventId -> best recommendation
  
  Process:
    1. Add all content-based recommendations (50% weight)
    2. For each collaborative recommendation:
       - If new event: add with 50% weight
       - If duplicate: blend scores, update source to 'hybrid'
  3. Sort by final score descending
  4. Apply filters (exclude completed/archived/already registered)
  5. Return top-3 with source attribution

FILTERING (Post-Scoring):
  - Exclude: completed, archived, cancelled events
  - Exclude: events user already registered for
  - Exclude: events that ended (endTime < now)
  - Include only: upcoming, live, draft status events

CACHING:
  Cache Key: userId
  Cache TTL: 5 minutes
  Eviction: Automatic on TTL expiry or manual invalidation
  Cache Size: In-memory Map structure

USE CASES:
  - Show "Recommended for You" section (logged-in only)
  - Improve user engagement through targeted suggestions
  - Adaptive: Learns from user behavior over time
  - Personalized experience per user

IMPLEMENTATION FILES:
  - Backend Service: /backend/src/services/ml/recommendationService.ts
  - Content-Based: /backend/src/services/ml/contentBased.ts
  - Collaborative: /backend/src/services/ml/collaborative.ts
  - Vectorizer: /backend/src/services/ml/vectorizer.ts
  - API Endpoint: GET /api/recommendations/:userId?limit=3
  - Training: POST /api/recommendations/admin/train

3. SENTIMENT ANALYSIS ALGORITHM
================================================================================

Algorithm Type: Multi-Stage Fusion Analysis
Provider: OpenAI GPT-4 + Local Rating Analysis
Error Handling: Graceful fallback on API unavailability

ARCHITECTURE (3-Stage Pipeline):
---------------------------------
Stage 1: Content Moderation (Safety Check)
Stage 2: Multi-Source Analysis (Rating + Text)
Stage 3: Consensus Voting

STAGE 1 - CONTENT MODERATION:
------------------------------
flagged = openAI.moderations.create(input: feedbackComment)

If flagged == true:
  Return immediately:
    sentiment: 'negative'
    confidence: 1.0
    flagged: true

Purpose: Remove inappropriate content before analysis

STAGE 2 - STAR-COMMENT FUSION:
------------------------------
Three possible scenarios:

Scenario A (Both Rating & Comment exist):
  sentimentFromRating = interpretRating(ratingValue)
  sentimentFromText = gptAnalysis(comment)
  finalSentiment = consensusVoting(sentimentFromRating, sentimentFromText)

Scenario B (Rating only):
  finalSentiment = interpretRating(ratingValue)
  confidence = 0.9 (high confidence for explicit rating)

Scenario C (Comment only):
  finalSentiment = gptAnalysis(comment)
  confidence = varies based on GPT confidence

RATING INTERPRETATION:
  1-2 stars → 'negative'
  3 stars -> 'neutral'
  4-5 stars → 'positive'

GPT ANALYSIS:
  Model: OpenAI GPT-3.5/GPT-4
  Prompt: Analyze feedback sentiment as positive/neutral/negative
  Response Format: { sentiment, confidence (0-1) }

CONSENSUS VOTING:
  If ratingOpinion == textOpinion:
    Use opinion with high confidence
  
  If opinions differ:
    Use text sentiment with reduced confidence
    Consider the strength of each signal

STAGE 3 - FINAL CLASSIFICATION:
-------------------------------
Decision Thresholds:

Positive: 
  - confidence > 0.6 AND sentiment == 'positive'
  - OR 5-star rating

Neutral:
  - 0.4 <= confidence <= 0.6
  - OR mixed signals (rating positive, comment negative)
  - OR 3-star rating

Negative:
  - confidence > 0.6 AND sentiment == 'negative'
  - OR 1-2 star rating

SCORE CONVERSION:
  Internal: 1-5 star scale
  If rating exists: use rating directly
  If text only: convert sentiment to score
    positive -> 4-5
    neutral -> 3
    negative -> 1-2

EVENT-LEVEL AGGREGATION:
------------------------
For each event, calculate:

eventSentimentAnalysis = {
  positive: (count of positive feedback / total feedback) * 100
  neutral: (count of neutral feedback / total feedback) * 100
  negative: (count of negative feedback / total feedback) * 100
  
  averageRating = SUM(allRatings * weight) / totalFeedback
  
  totalFeedback: number of feedback entries
  
  flaggedCount: number of moderated/flagged responses
}

API RESPONSE:
  Returns percentage breakdown + average rating

ERROR HANDLING:
---------------
OpenAI API Issues:
  - Status 429 (Rate Limited): Skip text analysis, use rating only
  - Status 401 (Auth Error): Log error, use local analysis only
  - timeout: Fallback to rating-based sentiment
  
Graceful Degradation:
  If GPT unavailable: Use rating and simple keyword matching
  If moderation fails: Skip moderation, proceed with analysis
  Never null response: Always return valid sentiment classification

REAL-TIME PROCESSING:
  Triggered: Immediately on feedback submission
  Async: Non-blocking, stored after analysis completes
  Indexing: Aggregated sentiment updated per event

USE CASES:
  - Display event sentiment breakdown (UI: pie chart of sentiment %)
  - Admin dashboard analytics and event quality scoring
  - Identify trending positive/negative events
  - Event quality indicator for ML recommendations
  - Alert admins to highly negative events (>70% negative)

IMPLEMENTATION FILES:
  - Service: /backend/src/services/sentimentService.ts
  - API Endpoint: POST /api/events/:eventId/feedback
  - Dashboard: Shows sentiment visualization

4. EVENT SEARCH AND FILTERING ALGORITHM
================================================================================

Algorithm Type: Multi-Criteria Relevance Ranking (Client-Side)
Time Complexity: O(n) where n = total events
Space Complexity: O(n) for indexing
Execution: React useMemo hook (optimization via memoization)

SEARCH INDEX CREATION:
----------------------
For each event, create searchable text:

searchText = [
  event.title.toLowerCase(),
  event.description.toLowerCase(),
  event.location.toLowerCase(),
  event.category.toLowerCase()
].join(' ')

Purpose: Single string for all-field searching

RELEVANCE SCORING ALGORITHM:
----------------------------
Initial Filter: Include events where searchText.includes(normalizedQuery)

For each matching event, calculate relevanceScore:

relevanceScore = 0

TITLE MATCHING (Highest Priority):
  if (title === normalizedQuery):
    score += 100
  else if (title.startsWith(normalizedQuery)):
    score += 80
  else if (title.includes(normalizedQuery)):
    score += 60

CATEGORY MATCHING:
  if (category === normalizedQuery):
    score += 40
  else if (category.includes(normalizedQuery)):
    score += 20

LOCATION MATCHING:
  if (location.includes(normalizedQuery)):
    score += 15

DESCRIPTION MATCHING (Lowest Priority):
  if (description.includes(normalizedQuery)):
    score += 10

WORD-BY-WORD MATCHING (Multi-word Queries):
  for each word in normalizedQuery:
    if (word.length > 2):  // Only significant words
      if (title.includes(word)):
        score += 5
      if (description.includes(word)):
        score += 2

TOTAL SCORE RANGE: 0-200+

RANKING:
--------
Sort results by relevanceScore descending:

results = matchedEvents.sort((a, b) => 
  b.relevanceScore - a.relevanceScore
)

Higher scores appear first (more relevant).

FILTERING (Applied After Search):
----------------------------------
Filter by Multiple Criteria:

1. CATEGORY FILTER:
   if (selectedCategory != 'all'):
     keep only events where event.category == selectedCategory

2. STATUS FILTER:
   if (statusFilter == 'all'):
     exclude: completed, archived, cancelled
     include: upcoming, live, draft
   else:
     include only: events.status == statusFilter

3. DATE RANGE (if implemented):
   keep events where eventDate >= startDate AND eventDate <= endDate

4. LOCATION FILTER (if implemented):
   keep events where event.location.includes(locationQuery)

Final Filter Formula (AND logic):
  keep if: (matchesCategory) AND (matchesStatus) AND (matchesDate)

SEARCH FLOW:
-----------
1. User types query
2. Normalize query: trim(), toLowerCase()
3. Build search index for all events
4. Filter for partial matches
5. Calculate relevance scores for matches
6. Sort by score descending
7. Apply category/status/date filters
8. Return filtered and ranked results

OPTIMIZATION:
--------------
Memoization: React useMemo hook
  - Recalculates only when [events] or [query] changes
  - Prevents expensive recalculation on every render
  - Result cached in memory

Early Exit: 
  - Return unfiltered array if query is empty
  - Short-circuit on single-character words

CLIENT-SIDE (Not Server Query):
  - All search happens in browser
  - No API calls needed for search
  - Instant results for good UX
  - Scalable to 5000+ events

FRONTEND FILTERING UI:
  - Status dropdown: All Status, Upcoming, Live, Completed, Archived
  - Category dropdown: All, Sports, Technology, Cultural, etc.
  - Sort options: Date, Popularity, Title
  - Search box: Real-time filtering

USE CASES:
  - Real-time search on /events page
  - Category filtering across all events
  - Status filtering (hide/show completed)
  - Multi-field searching (title, description, location, category)
  - Responsive instant results without server lag

IMPLEMENTATION FILES:
  - Hook: /client/src/hooks/useEventSearch.ts
  - Page: /client/src/pages/events.tsx
  - Page: /client/src/pages/home.tsx

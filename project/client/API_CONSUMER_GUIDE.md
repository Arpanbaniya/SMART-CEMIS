hooks/use-auth.ts\n`typescript\nGET /api/auth/user\n`\n- Fetches current user on app load\n- Used by multiple components for auth state\n\n### hooks/use-registration-status.ts\n`typescript\nGET /api/events/:eventId/check-registration\n`\n- Checks if user is registered for an event\n\n### hooks/useEventCreationPermission.ts\n`typescript\nGET /api/auth/event-creation-permission\n`\n- Checks if user can create events\n\n### hooks/use-websocket.ts\n`typescript\nWebSocket connection that listens for updates:\n- Event updates\n- Registration updates\n- Favorite updates\n- Feedback updates\n- Admin request updates\n`\n\n---\n\n## 📡 API Request Patterns\n\n### Using apiRequest() Utility\n`typescript\n// From client/src/lib/queryClient.ts\nconst response = await apiRequest('GET', '/api/events');\nconst response = await apiRequest('POST', '/api/auth/login', data);\nconst response = await apiRequest('PATCH', '/api/profile', updates);\nconst response = await apiRequest('DELETE', '/api/favorites/eventId');\n`\n\n### Using fetch() Directly\n`typescript\nconst response = await fetch('/api/events', {\n  method: 'GET',\n  credentials: 'include'\n});\n`\n\n### Using React Query\n`typescript\nconst { data } = useQuery({\n  queryKey: [\"/api/events\"],\n  queryFn: async () => await fetch('/api/events')\n});\n`\n\n---\n\n## 🔄 Real-Time Updates\n\n### WebSocket Consumer: use-websocket.ts\nListens for WebSocket events and invalidates React Query caches:\n\n`typescript\n// Invalidates when new event created\nqueryClient.invalidateQueries({ queryKey: [\"/api/events\"] });\n\n// Invalidates when event updated\nqueryClient.invalidateQueries({ queryKey: [\"/api/events\", eventId] });\n\n// Invalidates when favorite status changes\nqueryClient.invalidateQueries({ queryKey: [\"/api/favorites\"] });\nqueryClient.invalidateQueries({ queryKey: [\"/api/favorites/check\", eventId] });\n\n// Invalidates when feedback added\nqueryClient.invalidateQueries({ queryKey: [\"/api/events\", eventId, \"feedback\"] });\n\n// Invalidates when registration status changes\nqueryClient.invalidateQueries({ queryKey: [\"/api/events\", eventId, \"check-registration\"] });\n`\n\n---\n\n## 🔐 Authentication\n- All protected endpoints require `requireAuth` middleware\n- Authentication uses session-based cookies (Express Session)\n- Login response sets secure HTTP-only cookie\n- Frontend automatically sends cookies with each request via `credentials: 'include'`\n\n---\n\n## ⚠️ Common Error Codes\n\n| Code | Meaning |\n|------|----------|\n| 400 | Bad Request (validation error) |\n| 401 | Unauthorized (not logged in) |\n| 403 | Forbidden (insufficient permissions) |\n| 404 | Not Found (resource doesn't exist) |\n| 409 | Conflict (duplicate entry) |\n| 500 | Server Error |\n\n---\n\n## 📚 Related Files\n\n### Frontend API Integration\n- `lib/queryClient.ts` - API request utility and React Query setup\n- `lib/auth-utils.ts` - Authentication utilities\n- All hooks in `hooks/` folder consume these APIs\n\n### Backend API Definitions\n- `backend/src/server.ts` - Route mounting and server setup\n- `backend/src/routes/` - Individual route implementations\n- `backend/src/controllers/` - Business logic for API handlers\n\n---\n\n## 🚀 Development Notes\n\n1. **Vite Proxy**: Frontend proxies API requests to backend\n - See `client/vite.config.ts` for proxy configuration\n - `/api` requests are proxied to `http://localhost:3000/api`\n\n2. **React Query**: Used for data fetching and caching\n - Query keys match API endpoints for consistency\n - Automatic invalidation on mutations\n\n3. **WebSocket**: Real-time updates using Socket.IO\n - Connection established in `use-websocket.ts`\n - Broadcast messages trigger cache invalidation\n\n---\n\n*Last Updated: February 2024*\n"

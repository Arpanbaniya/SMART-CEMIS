# 🔗 SMART-CEMIS API Documentation\n## Shared APIs Between Frontend & Backend\n\n---\n\n## 📋 Quick Reference\n\nThis document describes all API endpoints that are **used by both the frontend and backend**. Each endpoint is documented with:\n- **Frontend Location**: Where in the client code the API is called\n- **Backend Location**: Route file where the endpoint is defined\n- **Authentication**: Required auth level\n- **Request/Response**: Data formats\n\n---\n\n## 🔐 Authentication Routes\n**Backend File**: `src/routes/authRoutes.ts`\n\n### POST /api/auth/login\n**Purpose**: Authenticate user with email and password\n\n**Frontend Usage**:\n- File: `client/src/pages/login.tsx` (line 31)\n- Uses `apiRequest(\"POST\", \"/api/auth/login\", ...)`\n\n**Request Body**:\n`json\n{\n  \"email\": \"user@example.com\",\n  \"password\": \"password123\"\n}\n`\n\n**Response (200 OK)**:\n`json\n{\n  \"user\": {\n    \"id\": \"userId\",\n    \"email\": \"user@example.com\",\n    \"firstName\": \"John\",\n    \"lastName\": \"Doe\",\n    \"role\": \"user|student_admin|super_admin\",\n    \"preference\": \"online|offline|both\",\n    \"isVerified\": true\n  }\n}\n`\n\n**Errors**:\n- `400`: Missing email or password\n- `401`: User not found or invalid password\n- `403`: Email not verified\n\n---\n\n### POST /api/auth/register\n**Purpose**: Register new user account\n\n**Frontend Usage**:\n- File: `client/src/pages/register.tsx` (line 63)\n- Uses `apiRequest(\"POST\", \"/api/auth/register\", ...)`\n\n**Request Body**:\n`json\n{\n  \"name\": \"John Doe\",\n  \"email\": \"user@example.com\",\n  \"password\": \"password123\",\n  \"preference\": \"online|offline|both\"\n}\n`\n\n**Response (201 Created)**:\n`json\n{\n  \"message\": \"Account created successfully! Check your email for verification.\",\n  \"email\": \"user@example.com\",\n  \"requiresEmailVerification\": true\n}\n`\n\n**Errors**:\n- `400`: Missing required fields\n- `409`: Email already registered\n\n---\n\n### POST /api/auth/verify-email\n**Purpose**: Verify user email with verification token\n\n**Frontend Usage**:\n- File: `client/src/pages/verify.tsx` (line 61)\n- Uses `apiRequest(\"POST\", \"/api/auth/verify-email\", ...)`\n\n**Request Body**:\n`json\n{\n  \"token\": \"verification-token-from-email\"\n}\n`\n\n**Response (200 OK)**:\n`json\n{\n  \"message\": \"Email verified successfully\"\n}\n`\n\n---\n\n### POST /api/auth/resend-verification\n**Purpose**: Send verification email again\n\n**Frontend Usage**:\n- File: `client/src/pages/verify.tsx` (line 98)\n\n**Request Body**:\n`json\n{\n  \"email\": \"user@example.com\"\n}\n`\n\n---\n\n### GET /api/auth/user\n**Purpose**: Get currently authenticated user\n\n**Frontend Usage**:\n- File: `client/src/hooks/use-auth.ts` (line 9)\n- Hook function: `fetchUser()`\n- Called on app initialization for auth state\n\n**Response (200 OK)**:\nSame as login response with user object\n\n---\n\n### GET /api/auth/event-creation-permission\n**Purpose**: Check if user can create events\n\n**Frontend Usage**:\n- File: `client/src/hooks/useEventCreationPermission.ts` (line 19)\n\n**Response (200 OK)**:\n`json\n{\n  \"canCreate\": true|false,\n  \"reason\": \"string (if false)\",\n  \"eventsCreated\": 0,\n  \"approvedRequests\": 0\n}\n`\n\n---\n\n## 📅 Event Routes\n**Backend File**:
